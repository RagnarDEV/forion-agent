# Forion Agent

مساعد برمجي يعمل على Cloudflare Workers: يستكشف مستودع GitHub، ويولّد التعديلات عبر Workers AI، ثم ينشئ فرعًا وPull Request للمراجعة، وينتظر فحوصات CI ويصلحها ذاتيًا عند فشلها.

## خط المعالجة

```
فحص ← استكشاف (اختياري) ← اختيار ← قراءة ← توليد ← مراجعة (اختيارية) ← نشر ← فحص CI وإصلاح (اختياري)
```

- **الاستكشاف الذكي**: حلقة متعددة الخطوات يستدعي فيها النموذج أدوات: `search_code` و`read_file` و`list_dir` و`list_issues` و`get_issue` و`get_pull_request`، و`add_comment` فقط عندما تطلب تعليقًا صراحةً (حد 3 تعليقات).
- **التوليد**: حتى 4 محاولات افتراضيًا (تُضبط 1–8). كل رفض (JSON تالف، edit لا يطابق، ملف مقتطع…) يُعاد للنموذج مع السبب ليصحح نفسه.
- **التعديل الجزئي**: الملفات الأكبر من 24KB تُعدَّل بـ `edits` (`search`/`replace` فريد ومطابق حرفيًا) بدل إعادة كتابتها. الحد الأقصى للملف 400KB.
- **عمليات الملفات**: إنشاء (حتى 100) وحذف ونقل ضمن Pull Request واحد.
- **المراجعة الآلية**: استشارية؛ مشاكلها المانعة تتيح إعادة توليد واحدة فقط، وملاحظاتها تُضاف لوصف الـ PR.
- **فحص CI والإصلاح الذاتي**: بعد إنشاء الـ PR ينتظر فحوصات GitHub؛ عند الفشل يقرأ السجل ويضيف commit إصلاح (حتى 4 جولات، الافتراضي 2). لا يدمج شيئًا. الفحوصات الخارجية بلا سجل مقروء (مثل Workers Builds) لا يحاول إصلاحها ويعرض رابطها.
- **قراءة فقط**: عند كتابة «دون تغييرات» أو `read-only` أو `without making any changes` لا يُنشأ فرع ولا PR.

## التوجيه الذكي للنماذج (Smart Model Router)

الوضع الافتراضي **Smart Auto**: يحلل الوكيل مهمتك (النوع، التعقيد، حجم السياق) ثم يختار النموذج لكل مرحلة بشكل مستقل: الاستكشاف · تحليل الملفات · التوليد · إصلاح CI · المراجعة. النماذج المدعومة: `@cf/zai-org/glm-4.7-flash` (الأساس)، `@cf/openai/gpt-oss-20b`، و`@cf/google/gemma-4-26b-a4b-it` (بديل Gemma 4).

**كيف يقرر**
1. **بوابات القدرة**: لا يدخل أي نموذج بديل في التوجيه قبل أن يجتاز «اختبار التوافق الحقيقي» على Worker الخاص بك (الإعدادات ← التوجيه). يختبر Gemma `max_completion_tokens` أولًا ثم `max_tokens` ثم الرسائل بدونهما عند الحاجة، ولا يُرسل أي معامل لم يثبت قبوله. لا تُمرَّر للنماذج البديلة معاملات GLM (`chat_template_kwargs` و`reasoning_effort`) أو معاملات غير موثقة.
2. **أولويات أولية معلنة** مبنية على التكلفة الموثقة: GLM أرخص بنحو 3 أضعاف على المدخلات (وهي الغالبة)، وGPT-OSS أخفض قليلًا في المخرجات فيُفضَّل في الاستدلال العميق (إصلاح CI والمراجعة).
3. **بيانات تاريخية مقاسة**: نسبة النجاح **بعد التحقق من الناتج** (حد ويلسون الأدنى، وتبدأ بعد 5 عينات وتتدرج حتى 20). السرعة لا تُعدّ دليل جودة ولا تكسر إلا تعادلًا قريبًا.
4. **التبديل**: عند مهلة أو نفاد سعة أو استجابة فارغة ينتقل إلى النموذج الآخر مرة واحدة لكل استدعاء (حتى 4 تبديلات للمهمة) بالرسائل والسياق نفسهما. وعند JSON غير صالح أو ناتج مرفوض يُخفَّض النموذج الفاشل في المحاولة التالية. عمليات GitHub تقع خارج الموجّه تمامًا فلا تتكرر بسبب التبديل، وفشل النموذج لا يخفف أي تحقق أمني.
5. **سقف الاستدعاءات**: 40 استدعاء نموذج للمهمة.

**الحصة المجانية فقط**
- حصة Workers AI المجانية 10,000 Neuron يوميًا **مشتركة بين كل النماذج**، وتتجدد 00:00 UTC؛ لذلك لا يوفّر التبديل حصة.
- الأسعار الرسمية (Neuron لكل مليون توكن، مدخل/مخرج): GLM-4.7-Flash `5,500 / 36,400`، GPT-OSS-20B `18,182 / 27,273`، وGemma 4 `9,091 / 27,273`. Gemma 4 يملك سياقًا قدره `256,000` توكن ويدعم Function Calling وReasoning وVision وفق وثائق Cloudflare.
- المحاسبة من `usage` الذي يعيده النموذج فعليًا؛ وإن غاب فحد أعلى رياضي من البايتات (وليس تخمينًا) معلَّم «تقريبي».
- ميزانية داخلية قابلة للضبط (افتراضيًا 9000 يوميًا و4000 للمهمة، ولا تتجاوز 10,000 أبدًا). تتوقف النماذج قبل الاستدعاء إن كانت تكلفته المتوقعة تتجاوز المتبقي، وعند الخطأ `3036` تتوقف فورًا بلا إعادة محاولة ولا تبديل ولا أي شيء مدفوع.
- العداد محلي ويحسب ما يستهلكه هذا الوكيل فقط؛ الحارس النهائي هو رفض Cloudflare.

**الخصوصية**: الإحصاءات أعداد ومجاميع فقط (نموذج · مرحلة · نوع مهمة)، بلا أسرار ولا نصوص ولا محتوى مستودعات ولا أسماء ملفات، وتُحفظ في متصفحك وتُرسل مع كل مهمة.

**التشخيص**: تعليق `PIN_MODEL` في `wrangler.toml` يثبّت نموذجًا واحدًا لكل المراحل ويعطّل التوجيه والتبديل. الواجهة لا تتيح اختيارًا يدويًا للنموذج.

**الاختبارات**: الاختبارات الآلية للموجّه تعمل بربط AI وهمي (محاكاة منطق)، ولا تثبت عمل النموذج على حساب Cloudflare. التحقق الحي من Gemma وGPT-OSS يتم فقط بزر «اختبار التوافق الحقيقي» على Worker منشور، ويستهلك Neurons من الحصة اليومية المشتركة البالغة `10,000` Neurons لجميع النماذج، وليس حصة مستقلة لكل نموذج.

## الواجهة

- **الإعدادات** (زر ⚙): عام · التوجيه · المهارات · الحساب. في «التوجيه»: عداد الحصة، التبديل التلقائي، المراجعة (معطّلة/تلقائية/دائمة)، الميزانيات، اختبار التوافق، وإحصاءات الأداء.
- **أثناء المهمة**: يظهر النموذج المستخدم لكل مرحلة وسبب اختياره باختصار، وتنبيه عند التبديل أو عند نفاد الحصة.
- **المهارات**: تعليمات إضافية للنموذج. مدمجة (تُنسخ وتُعدَّل) ومخصصة (إضافة/تعديل/حذف/استيراد/تصدير JSON). أوضاع التفعيل: تلقائي · دائم · معطّل.
- **زر الإيقاف** أثناء المهمة.
- **رمز الإدارة**: لصق من الحافظة مع تنظيف تلقائي، «تذكّرني على هذا الجهاز» (30 يومًا)، ودخول تلقائي.
- **تطبيق ويب قابل للتثبيت (PWA)**: مانيفست وService Worker وأيقونات تُولَّد من الخادم.

## الحدود

كل الحدود في `src/config.js`: الرسالة 50000 حرف، السجل 16 رسالة (حتى 120000 حرف)، 12 ملفًا للتحليل (240KB)، ومهلة توليد 10 دقائق للمحاولة وسقف كلي 30 دقيقة للمهمة.

**ميزانية الاستدعاءات الخارجية**: الخطة المجانية تسمح بـ 50 استدعاءً خارجيًا للطلب. يحسب الوكيل كل استدعاء (GitHub والنماذج) بميزانية 45، ويحجز لما بعد الاستكشاف، ولا يبدأ النشر دون 7 استدعاءات متاحة، ويتوقف بتحكم قبل الحد. ارفعها بـ `SUBREQUEST_LIMIT` فقط إن سمحت خطتك.

## الإعداد

الأسرار (في Cloudflare أو `.dev.vars` محليًا، راجع `.dev.vars.example`):

- `ADMIN_TOKEN`: رمز الدخول. يمكن وضع عدة رموز (سطر أو فاصلة) لتدوير الرمز دون انقطاع. يُقبل في `X-Admin-Token` أو `Authorization: Bearer`، وبعد 8 محاولات خاطئة يُحظر العنوان 10 دقائق.
- `GITHUB_TOKEN`: رمز GitHub (Fine-grained) بالصلاحيات: Contents وPull requests وIssues (Read and write)، وActions وChecks (Read)، وMetadata (Read). أضف **Workflows (Read and write)** إن أردت أن يعدّل الوكيل `.github/workflows`.

المتغيرات في `wrangler.toml`:

- `MODEL`: النموذج الأساسي (GLM-4.7-Flash). لا حاجة لتغييره؛ التوجيه آلي.
- `PIN_MODEL` (اختياري، للتشخيص فقط): يثبّت نموذجًا ويعطّل التوجيه.
- `SUBREQUEST_LIMIT` (اختياري): ميزانية الاستدعاءات الخارجية للطلب (الافتراضي 45).
- `AUTO_MERGE`: `"false"` افتراضيًا. لا تفعّله قبل تفعيل Allow auto-merge وحماية الفرع مع فحوصات مطلوبة.

## هيكل المشروع

```
src/
  index.js            توجيه الطلبات والأيقونات
  config.js           كل الحدود والمهل
  routes/             repos · task · skills · icons · router (اختبار التوافق)
  lib/                ai · auth · budget · github · history · intent · options · paths · png · security · stream …
  pipeline/           scan · explore · select · read · generate · patch · publish · verify
  router/             router · policy · classify · catalog · usage · ledger · stats · probe · review · call-model · errors · input
  skills/             registry · context · builtin
  tools/              github-tools (أدوات الاستكشاف)
public/               الواجهة (index.html · css/ · js/ · sw.js · manifest.webmanifest)
tests/                node:test (منطق الموجّه، المحاكاة، فحوص الواجهة الثابتة، واستيراد كل الوحدات)
.github/workflows/    agent-check.yml (اختبارات + صياغة)
```

## CI

`.github/workflows/agent-check.yml` يشغّل `npm test` وفحص صياغة JS وJSON على كل Pull Request. اسم الفحص يظهر للوكيل عند قراءة السجلات.
